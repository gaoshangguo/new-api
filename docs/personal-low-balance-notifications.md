# 个人低余额通知

个人钱包余额提醒支持站内信和邮件独立开启，可同时开启。不会修改余额、扣费规则或企业项目提醒。

## 用户配置

进入「个人设置 → 通知」，开启「低余额站内信」和/或「低余额邮件通知」，填写提醒阈值并保存。阈值使用当前余额的显示单位；如果系统显示积分，输入 `20` 即表示低于 20 积分提醒，而不是 20 个内部 quota 单位。等于阈值时不提醒。

通知邮箱为空时使用账户邮箱。站内信位于右上角铃铛的「站内信」页签，包含未读数，支持标记已读及加载历史消息。消息及已读状态保存在服务器，只允许本人访问，不依赖浏览器 localStorage。

新用户默认开启站内信。邮件默认兼容原有设置：原先使用邮件（或未选择通知方式）的用户默认开启邮件；原先使用 Webhook/Bark/Gotify 的用户不会被自动开启邮件，可手动开启独立邮件开关。原有外部推送方式继续生效，邮件不会走两条路径重复发送。

## 管理员配置

邮件使用系统已有 SMTP 配置（服务器、端口、发件人、账号及认证/TLS 设置）。需要有效的用户邮箱及可用 SMTP 服务器。未配置邮件或发送失败不影响站内信，邮件会在后续扫描中重试。功能不自动配置 SMTP，也不发送测试邮件。

启动时自动迁移 `user_notifications` 和 `user_low_balance_states` 两张表，使用兼容 SQLite/MySQL/PostgreSQL 的 GORM 操作。

钱包消费结算后异步检查余额；系统任务同时兜底扫描，覆盖已经低余额、批量落库以及无新请求的账号：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `USER_LOW_BALANCE_TASK_ENABLED` | `true` | 是否启用定期扫描；不关闭消费后的即时检查 |
| `USER_LOW_BALANCE_TASK_INTERVAL_MINUTES` | `5` | 扫描间隔，限制为 1–1440 分钟 |

扫描复用现有 SystemTask 调度器，仅在主节点运行。设置 `NODE_TYPE=slave` 的节点不会执行兜底扫描，部署必须有正常运行调度器的主节点。前端登录后每分钟刷新消息；邮箱失败重试至少间隔五分钟。原始余额与内部阈值保持不变，已有用户的阈值不被自动重置为 20 积分。

## 去重与恢复

连续低余额期间，每个开启的渠道只生成/成功发送一次提醒。标记已读不会触发新提醒；关闭渠道不会删除历史消息。余额恢复至阈值及以上后再次低于阈值，会开启新的提醒周期。充值、兑换、人工加款和签到等正常入账路径主动恢复提醒状态；直接修改数据库或其他自定义路径由定期扫描兜底，需让扫描观察到恢复的余额。

站内信先持久化，邮件使用数据库租约防止多节点或扫描与结算并发重复发送。邮件租约为十分钟；失败五分钟后可重试。SMTP 本身不支持事务：若邮件已投递但进程在记录成功前崩溃，重试可能产生重复邮件，因此投递语义为至少一次，而不是严格恰好一次。

## API

以下接口均要求用户认证并禁止缓存：

- `GET /api/user/notifications`：最新 50 条本人消息及所有消息的未读数。
- `GET /api/user/notifications?before_id=<id>`：加载更早的消息。
- `POST /api/user/notifications/<id>/read`：幂等标记本人的消息已读。其他用户的 ID 与不存在的 ID 均返回 404。
- `PUT /api/user/setting`：新增可选布尔字段 `low_balance_in_app_enabled`、`low_balance_email_enabled`。缺省兼容旧客户端；`quota_warning_threshold` 仍为内部 quota 正整数，范围 1–2147483647，前端负责显示单位换算。

上线前应在测试环境配置 SMTP，使用测试账户确认低余额时同时收到站内信和邮件，持续消费不重复提醒，充值恢复后再消费会重新提醒。
