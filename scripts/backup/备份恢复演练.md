# 备份与恢复演练（P0-30）

## 目标

- 定时/异地备份三数据库（SQLite、MySQL、PostgreSQL）；
- 账务与审计表随全库备份单独保护（余额账本、审计、消费投影均在主库，随库备份）；
- 恢复演练记录 RPO（数据丢失窗口）与 RTO（恢复耗时）。

## 脚本

| 脚本 | 用途 |
| --- | --- |
| `scripts/backup/backup.sh` | 备份：`backup.sh <sqlite\|mysql\|postgres> <目标目录>`；设置 `OFFSITE_DIR` 可二次异地拷贝 |
| `scripts/backup/restore.sh` | 恢复：`restore.sh <sqlite\|mysql\|postgres> <备份文件>` |

环境变量：

| 变量 | 说明 |
| --- | --- |
| `SQLITE_DSN` | SQLite 文件路径（默认 `/data/new-api.db`） |
| `MYSQL_DSN` | MySQL 连接串：`user:pass@tcp(host:port)/db?charset=utf8mb4` |
| `PG_DSN` | PostgreSQL 连接串：`postgres://user:pass@host:5432/db` |
| `OFFSITE_DIR` | 可选：备份后二次拷贝目录 |

## 建议调度

```cron
# 每日 02:00 备份，保留最近 14 份（叠加 OFFSITE_DIR 做异地拷贝）
0 2 * * * /path/to/new-api/scripts/backup/backup.sh postgres /backup/weekly
0 2 * * * find /backup/weekly -name '*.dump.gz' -mtime +14 -delete
```

## 账务单独保护

余额账本（`balance_ledgers`）、业务审计（`business_audit_events`）、消费投影
（`business_consumptions`）、调账订单（`manual_credit_requests`）均位于主库，
随全库备份一并覆盖。若需更细粒度，可在备份后对上述表做针对性导出：

```sql
-- MySQL / PostgreSQL 示例（账务审计单独快照）
SELECT * FROM balance_ledgers WHERE created_at >= NOW() - INTERVAL 1 DAY;
```

演练步骤：

1. 在测试实例（或同版本 Docker 容器）执行 `restore.sh` 恢复最近备份；
2. 启动服务，核对 `options`、`users`、`balance_ledgers`、`business_audit_events` 行数与业务抽样；
3. 记录 RTO（开始恢复到服务可用）；RPO 由备份频率决定（建议 ≤24h，重要平台可缩短至 1h）；
4. 将结果填入上表并归档本目录。
